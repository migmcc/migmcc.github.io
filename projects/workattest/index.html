WorkAttest

An original, local-first project for linking request, authorisation, evidence and validation through verifiable accountability receipts.

Source and README ↗
PythonEd25519Local-firstMVP / source-only
The problem

Evidence can be difficult to connect to a decision.

AI-assisted work can involve requests, authorisations, work evidence and later checks. WorkAttest is intended to make that chain easier to inspect without presenting the receipt as a replacement for human judgement.

What the repository describes

Signed, offline-verifiable receipts

  • Links request, authorisation, evidence and validation records.
  • Uses Ed25519 signed receipts that can be verified offline.
  • Keeps the workflow local-first rather than sending work data to a hosted service.
Authorship and status

Original project by Miguel Santos. Its public repository is the source of truth for the current implementation, documentation and limitations.

MVP scope and trust limits

Evidence is not a production security guarantee.

WorkAttest is presented here as an MVP, source-only project. It does not claim that code is correct, that a model is reliable, or that an approval is competent.

  • Its development key storage is not a production security control; private signing keys need suitable custody, such as an approved KMS, HSM or equivalent process, before production use.
  • Verification commands are defined by a trusted operator. WorkAttest records their result, but does not establish that an arbitrary command or configuration is safe.
  • Receipts bind the documented process and artefacts; they do not replace a security audit, human judgement or regulatory review.

Availability

MVP / source-only. No packaged release or hosted service is presented here.

Who it is for

People exploring clearer accountability records in AI-assisted workflows.

Demonstration

No separate web demonstration is presented here. Consult the repository documentation and examples before relying on it.
